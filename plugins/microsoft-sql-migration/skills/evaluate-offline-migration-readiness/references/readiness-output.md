# Output Format: Readiness Assessment (No Perf Data)

Use this output template for readiness assessment without a SKU recommendation.

> **HARD OUTPUT CONTRACT:** The final assessment response must use the complete
> template below. Do not substitute a one-line or prose summary, even after a
> retry or when the user declines SKU recommendation. CLI tool-activity lines
> such as `Shell`, `MD`, and `Asked user` are execution trace and are not part of
> this response template.

---

## Processing Logic

On assessment JSON received:

1. Parse compatibility findings (per database + server level)
2. Classify blockers by severity: Critical | Warning | Info
3. Count readiness per target: Ready | Blocked | Needs Review

---

### Counting databases and readiness

- Include user databases only. Exclude `master`, `model`, `msdb`, and `tempdb`
  from counts, readiness summaries, issue lists, and displayed database names.
- For Local JSON, set `{assessed}` to the online user-database count in
  `Servers[0].Databases[]`. List offline user databases separately. Treat an
  online database with no findings as assessed and Ready.

---

## Skill Response Template

```
SKILL: {skill-name}  |  {instanceName}
══════════════════════════════════════════════════════════

Assessment Summary
──────────────────
  SQL Server Instance:   {instanceName}
  Databases assessed:    {assessed}   ({offline} offline — show this note only when {offline} > 0)

Migration Readiness
───────────────────

  - Azure SQL Managed Instance
    Instance Readiness — {Ready | Not Ready}
      Blocking issues:  {count}
      Warnings:         {count}
    Database Readiness
      {x} of {assessed} databases ready [{DB names list}]
      {z} of {assessed} databases not ready [{DB names list}]

  - Same for Azure SQL Database

  - SQL Server on Azure VM
    Always Ready (IaaS lift-and-shift, no compatibility barriers)

  (If any DB list has more than 20 databases, truncate with "...")

REPORT
──────
  Local source:
  📄 {actual generated HTML report path}
  (If no HTML was generated, show the actual JSON report path instead.)

```

Use the report file generated by the CLI. Do not include the SKU sizing question
inside this report; the calling skill asks it separately afterward.
